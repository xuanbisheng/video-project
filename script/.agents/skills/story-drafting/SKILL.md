# 故事成稿

在用户选定故事方案后、剧本写作前使用本 Skill。它负责把一个创意写成完整、连贯、可制作的故事成稿；本阶段不写 screenplay，不写场次卡，不写分镜或视频生成提示词。

## 输入

- 用户选定的故事方案或明确的原创创意；
- 项目简报：时长、平台、受众、语言、类型、基调和内容边界；
- AI 视频或拍摄限制；
- 用户确认的参考作品，只作为气质或结构参考。

如果时长、类型或结局方向会明显改变故事，先标为待确认，不要默默替用户决定。

## 创作要求

1. 先明确故事定位：类型、基调、观众承诺、时长和制作边界。
2. 先填写故事骨架：主角、当前处境、具体目标、强动机、时间压力、主要阻碍、失败代价、转折、关键选择和结尾情绪。骨架不成立时先修正，不用华丽设定掩盖漏洞。
3. 写出完整故事正文，使用清晰的起因、目标、阻力、升级、危机、高潮、结局和最后画面；不要停在设定展示或一句话梗概。
4. 每个关键行为都必须能由角色的欲望、已知信息和现场条件解释。自由发挥可以加入高概念规则、AI 原生视觉或荒诞机制，但必须形成因果闭环。
5. 让结尾兑现前文已经建立的规则或情感承诺。反转要有前置线索，不得在最后临时添加解决问题的新事实。
6. 适配短片时长：控制主要角色、地点、道具和支线数量；每一段都要改变局势、增加代价、揭示信息或迫使选择。
7. 把抽象心理改写为可见动作、可听声音、可交互的物件或空间关系；不要用“他很害怕”“她终于释怀”代替戏剧行为。
8. 面向 AI 视频时，优先设计可拆成 5—8 秒镜头的视觉动作、重复母题、固定角色外观和可后期添加的字幕/音效。为主要角色、道具、场景设定少量稳定的视觉锚点。
9. 涉及动物时，不以伤害、危险食物、窒息或惩罚制造笑点；优先使用误会、欲望、伪装、道具和关系反转。

## 视觉叙事约束

- 每个段落先写它要让观众知道或感受到什么，再选择动作和信息顺序；不要为了“画面漂亮”堆镜头奇观。
- 关键发现按“空间/处境 → 动机或目标 → 行动 → 异常 → 反应 → 下一步钩子”释放，避免一次解释完所有信息。
- 反转前必须留下可回看的物件、动作、色彩或声音线索；结尾用一个可见动作收住情绪。

## 必须包含的内容

- 标题与项目元数据；
- 故事定位与一句话故事；
- 角色与关系；
- 世界规则或现实条件；
- 完整故事正文；
- 故事节拍与关键转折；
- 反转/结局的逻辑闭环说明；
- 视觉风格简报：构图倾向、视点、光源动机、主色与情绪、材质和需要保持的视觉锚点；
- AI 视频表达建议或制作风险；
- 故事确认区。

## 输出

生成 03_story.md。文件状态必须标记为“待用户确认”，并明确：用户确认故事前，不得调用 screenplay-writing。

## 交接

用户确认 03_story.md 后，才可以调用 screenplay-writing 生成 05_screenplay_v1.md。剧本写作阶段只能把已确认的故事成稿作为故事、人物、规则、结构和结局依据；如果用户要求改变故事，先回到本 Skill 修订 03_story.md。
