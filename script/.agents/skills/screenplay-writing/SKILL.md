# 短片剧本写作

只有在用户确认 03_story.md 后，或用户明确要求修改已有剧本时，才能使用本 Skill。已确认的故事成稿是人物、结构、规则和结局的最高依据。

## 写作规则

1. 保留已确认的前提、人物动机、主要节拍和结局。如果认为必须改变，先标记变更原因，不能默默改写故事。
2. 使用现在时书写可见、可执行的动作。除非能够被画面或声音表现，否则不要使用小说式内心独白。
3. 每场戏都要有明确目的、冲突和转折。尽量晚进入场景，在戏剧信息或决定落地后及时离开。
4. 对白必须符合说话人的身份和性格，简洁并推动行动。避免角色不可能自然说出的说明性对白。
5. 遵守已确认的 03_story.md；不得擅自改变其中的连续性事实、结构和结局。
6. 制作复杂度必须符合项目简报。不要擅自加入昂贵场景、群演、大型特效或新的主要人物；如确有必要，必须说明影响。
7. 本 Skill 只写剧本。除非用户另行要求制作拆解，否则不要加入镜头表、图片提示词或视频生成提示词。

## Markdown 剧本格式

初稿生成 05_screenplay_v1.md，确认后的修改稿生成 07_final_screenplay.md。至少包含：

- 片名和项目元数据；
- 包含内/外景、地点和时间的场景标题；
- 简洁的动作段落；
- 角色名和对白；
- 只在必要时使用括号说明；
- 只有能够明确剪辑意图时才使用转场；
- 结尾附预计时长和已知制作注意事项。

## 修改模式

根据 06_review_report.md 修改时，先列出本次要处理的问题编号，再用最小改动解决问题，并重新检查正典、连续性、节奏和结局。不要为了润色而重写没有问题的场次。

## 交接规则

完成初稿后必须停止，等待用户授权剧本审查。完成修改后，要列出已解决的问题和仍然开放的问题。
