# 短片剧本生产流程

本文件定义短片剧本项目的 Agent 编排方式。它是项目总控 Agent 的路由协议；具体专业方法仍以各个 Skill 的 SKILL.md 为准。

## Agent 角色

- 项目总控 Agent / Showrunner：理解项目简报、选择 Skill、管理产物、请求用户确认并处理冲突。
- 题材研究 Agent：先收集用户创意、类型、目标平台和市场，再调用 video-trend-research 搜索相近题材，返回研究依据和恰好 3 个原创故事简介。
- 故事开发 Agent：调用 short-film-development 和 story-drafting，生成故事方案和可确认的故事成稿。
- 编剧 Agent：调用 screenplay-writing，负责剧本初稿和修改稿。
- 剧本医生 Agent：调用 screenplay-review，负责诊断剧本，不能默默改写原稿。

## 必要输入

题材研究 Agent 的第一步收集：用户创意、类型、目标平台和市场/地区。Agent 先搜索相近题材，再围绕用户创意产出恰好 3 个原创故事简介。用户可以选择一个方案；如果 3 个都不符合，可以重新调用 Agent 产出下一组 3 个。时长、受众、基调、语言、内容边界、参考作品和制作限制仍可在后续阶段补充。如果缺少的信息会明显改变故事，应先询问用户。假设记录在项目产物中。

## 状态机

1. 题材研究 Agent：收集用户创意、类型、目标平台和市场，调用 video-trend-research，生成相近题材研究反馈和恰好 3 个故事简介。
2. 题材确认：停止，等待用户确认搜索反馈并选择题材方向。
3. 故事方案：展示 Agent 返回的 3 个故事简介；若用户全部否决，可再次调用 video-trend-research 生成下一组 3 个方案；用户选定后生成 02_concept_options.md。
4. 方案确认：停止，等待用户选择一个方案或提出受控合并方案。
5. 故事成稿：调用 story-drafting，生成 03_story.md。
6. 故事确认：停止，等待用户确认故事正文、人物、规则、时长和结局。
7. 剧本初稿：调用 screenplay-writing，读取已确认的 03_story.md，生成 05_screenplay_v1.md。
8. 初稿确认：停止，等待用户授权审查。
9. 剧本审查：调用 screenplay-review，生成 06_review_report.md。
10. 修改决策：停止，等待用户选择要处理的问题等级或范围。
11. 最终稿：以修改模式调用 screenplay-writing，生成 07_final_screenplay.md，并列出已解决和仍开放的问题。

故事成稿一次性承载人物、关系、世界条件、节拍、反转和结局；本流程不再设置独立的设定正典或结构大纲阶段。

## 产物规则

- 产物放在项目输出目录，默认是 output/short-film/<project-slug>/。
- 不覆盖已经确认的产物。只有用户明确要求时才创建新版本或修改原版本。
- 下一阶段必须显式读取上一阶段的产物，不能只依赖隐藏的对话记忆维护正典。
- 影响创作建议的每条研究结论都要保留来源和具体观察日期。
- 除非用户明确要求回到故事成稿修改，否则所有剧本修改都必须遵守已确认的 03_story.md。

## 路由规则

- 使用能够覆盖当前状态的最小 Skill 集合。
- 故事方案和 03_story.md 未确认前，不得调用 screenplay-writing。
- 没有剧本初稿且用户未授权前，不得调用 screenplay-review。
- 用户只是修改已有剧本时，不要自动调用题材研究，除非用户明确要求当前市场证据。
- 本流程暂不调用分镜、图片生成或视频提示词 Skill；这些属于后续制作阶段。

## 确认话术

每个确认点都要展示产物路径、概括本阶段变化、列出需要用户决定的内容，然后停止。用户回复“确认”“选择方案 2”“按 A+B 修改”或“进入下一步”，只要能明确对应下一状态，就可以继续。

## 完成标准

只有当 07_final_screenplay.md 已生成、最终稿通过用户要求的审查范围、未解决问题已公开说明，并且输出目录包含已确认的中间产物时，项目才算完成。
