# Multi Agent Workflow

这是一个逻辑分工协议。默认由一个 Agent 在同一会话内按阶段执行；需要真正并行时才将阶段委派给子 Agent。无论是否并行，阶段顺序和交付物不变。

## 阶段顺序

1. `script-parser`：识别人物、地点、时间、动作、情绪、道具、转折和潜在视觉线索；不写最终提示词。
2. `story-checker`：用目标、动机、阻碍、转折、选择、代价、落点检查故事可拍性；问题先列为待确认。
3. `scene-splitter`：拆场景和视频单元；长视频单元不超过 15 秒，写起始状态、结束状态和下一条衔接。
4. `asset-planner`：决定角色、场景、道具、服装、关键特效、风格资产和参考图职责。
5. `asset-builders`：分别稳定角色、场景、道具和风格规则；固定描述写入资产 ID。
6. `shot-planner`：每个单元设计 2-4 个镜头任务，写景别、机位、运动、构图、光影、声音和剪辑点。
7. `prompt-writer`：按目标模型输出通用版和专用版；不新增剧情。
8. `continuity-checker`：检查人物、服装、道具、站位、轴线、光线、声音、时长和前后状态。
9. `exporter`：汇总成可交付文件，并列出通过、需确认、失败项。

## 阶段门

- 没有一句话故事或关键动机不清，不进入镜头提示词。
- 没有资产锁定项，不生成需要角色/道具连续性的镜头。
- 没有起始/结束状态，不交付多单元视频提示词。
- 连续性质检存在失败项时，先修正受影响镜头，再导出。

## 最小交付包

项目说明、剧本解析与节拍、场景/视频单元、角色/场景/道具资产、风格规则、通用生图与 Midjourney 资产提示词、镜头规划、通用视频提示词与 H3 提示词、连续性质检和待确认问题。用户限定交付范围时按要求缩小。
