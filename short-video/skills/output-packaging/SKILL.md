# Output Packaging

统一管理分镜、视频提示词、资产提示词和生成执行表的交付目录。

## 三部分最低交付

每次面向用户的影视项目产出都必须是一个完整运行包，不得只交付单一文件。运行目录直接包含以下三部分：

1. **资产库**：`generic-image-prompts.md`、`midjourney-prompts.md`。前者是通用生图资产提示词，后者是 Midjourney 资产提示词；两份文件的 Asset ID 和锁定设定必须一致。
2. **分镜剧本**：`ai-storyboard-script.md`，需要执行表时同时包含 `ai-shot-generation-sheet.md`。
3. **视频提示词**：`generic-video-prompts.md`、`h3-video-prompts.md`；用户指定其他模型时，再增加对应专用文件。

`run-manifest.md` 不属于上述三部分，但每个运行目录都必须有，并按“资产库 / 分镜剧本 / 视频提示词”列出文件、状态和校验结果。

## 角色审核闸门例外

角色设计审核是完整项目包之前的受控中间阶段。该阶段允许运行目录暂时只包含剧本解读摘要、`character-design-review.md` 和 `run-manifest.md`，运行状态必须为 `待角色审核`，不能标记为 `已完成`。

用户明确确认角色设计后，继续在同一个运行目录生成资产库、分镜剧本和视频提示词三部分；最终交付仍必须满足三部分最低交付。

用户要求修改角色时，创建新的运行目录保存新的审核版本，并在 manifest 中记录基于的旧运行；未确认前不得进入下游流程。

如果用户只点名其中一部分，主 Agent 仍生成完整三部分。只有遇到真实阻塞时才允许缺少文件；此时运行目录保留为 `失败/未完成`，`run-manifest.md` 记录缺失项、原因和补齐依赖，不能把半成品标记为完成，也不要用空壳文件冒充交付物。

## 目录规则

- 每次执行（包括同一剧本的修订、补充或换模型重跑）必须新建一个运行目录，不得覆盖旧运行目录。
- 目录格式：`outputs/<project-slug>/run-<YYYYMMDD-HHmmss>[-<序号>]/`。
- `project-slug` 使用项目或剧本名称的小写 kebab-case；时间使用本地执行时间。相同秒再次执行时追加两位序号，例如 `-02`。
- 项目目录下只能放运行目录；不得把交付文件直接写入 `outputs/<project-slug>/`。
- 一次执行产生的所有交付文件都放入同一个运行目录，包括上述三部分、镜头生成执行表、质检记录和必要的项目摘要；三部分文件不得分散到不同运行目录。

## 执行顺序

1. 开始任务时先确定项目 slug 和唯一运行目录，并创建目录。
2. 在运行目录内生成所有文件；文件名可以沿用各 Skill 的默认文件名。
3. 生成 `run-manifest.md`，记录运行时间、来源剧本、使用的 Agent/Skill、交付文件清单和与上一运行的关系。
  运行清单必须按三部分登记每个文件；文件缺失时登记状态 `未生成`，并说明原因。
   三部分文件全部存在且通过质检后，运行状态才可标记为 `已完成`。
4. 交付时只引用本次运行目录中的文件；历史运行目录保持只读。

## 修订与失败重跑

- 修订不能覆盖原文件，必须创建新的运行目录，并在 manifest 中注明 `基于运行：<旧运行目录>`。
- 任务失败或只生成部分文件时，也保留该运行目录，在 manifest 中标记状态和失败原因；下一次重跑使用新的运行目录。
- 不把临时缓存、调试日志或中间文件写到项目目录根部；确需交付的中间结果一并放入本次运行目录。

## 最低交付检查

- 运行目录唯一且可由目录名判断时间。
- 所有本次交付文件位于同一运行目录内。
- `run-manifest.md` 的清单与实际文件一致。
- 没有覆盖、移动或删除历史运行目录中的文件。
