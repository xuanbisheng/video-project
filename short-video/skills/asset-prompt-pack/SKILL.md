# Asset Prompt Pack

把影视剧本或项目设定中的视觉资产转成可复用的资产提示词包。资产类型包括角色、道具、场景、交通工具、服装、建筑、怪物、动物和关键特效元素。

## 核心交付

每次资产提示词任务必须输出两个独立 Markdown 文件：

1. `generic-image-prompts.md`：模型无关的通用生图提示词，适用于 Flux、SDXL、Imagen、其他文生图/图生图工具。
2. `midjourney-prompts.md`：遵循当前 Midjourney 默认版本 V8.2 的专用提示词，参数和参考图写法单独处理。

不要把两种提示词混在一个文件里。两份文件中的资产编号、资产名称、连续性锁定项和版本号必须一一对应。

所有文件必须先调用 `output-packaging`，写入新的 `outputs/<project-slug>/run-<YYYYMMDD-HHmmss>[-<序号>]/` 运行目录；不得直接写入项目目录或覆盖历史运行。运行目录还必须包含 `run-manifest.md`，列出本次实际生成的文件。

## 适用范围

当用户要从剧本提取角色、道具、场景等资产，或要求生成角色设定图、道具设定图、场景概念图、资产参考图时使用。单纯生成一张自由创作图片时不必启用本 Skill。

## 默认资产流程

1. 提取资产：从剧本中识别角色、道具、场景、服装、交通工具、动物和关键视觉元素。
2. 建立资产圣经：锁定名称、身份、外观、比例、材质、色彩、时代、使用痕迹和不可改变项。
3. 确定展示目标：按用户用途选择角色肖像、全身、表情、服装、局部或多角度图；三视图仅在明确要求或外观审阅确有需要时输出。道具优先输出孤立物、细节和尺度；场景优先输出空间全貌、入口关系、材质和光线。
4. 生成通用提示词：写出主体、展示方式、材质、环境、光线、摄影/构图、色彩和一致性约束，并提供通用负面提示词。
5. 生成 Midjourney 提示词：遵循 V8.2 简洁自然语言、参考图与参数末尾规则；只使用当前版本可解释的参数。
6. 检查连续性：确保同一资产在两份文件中外观、颜色、材质、比例和叙事功能一致。

## 资产分类要求

- **角色**：姓名/代号、年龄段、体型、脸部特征、发型、肤色、服装、鞋、配饰、姿态、表情、比例和背景。
- **角色参考图**：按资产用途选择肖像、全身、局部或多角度设定图；三视图仅在用户要求或确有外观审阅需求时制作，不是 H3 的前置资产。视频中会出现手、鞋、腰部、纹理或特殊配饰时，按需增加局部特写。进入 H3 等视频模型的多模态参考时，仅在身份连续性确有需要时提供单主体、单视角的独立图片，并标明其锁定职责；不要把三视图拼图直接当作 H3 的人物身份参考。
- **道具**：名称、类别、功能、轮廓、尺寸、材料、颜色、磨损、结构细节、握持方式、尺度参照和展示角度。
- **道具参考图**：除英雄角度外，增加关键功能部位、使用状态和与人物/桌面/门框的尺度图。
- **场景**：地点、空间布局、建筑/自然元素、材质、入口和主要物件关系、时间、天气、光源、色彩和镜头视角。
- **场景参考图**：至少包含空间全貌和一张关键机位/走位视图；复杂走位同时输出线稿故事板或关键帧说明。
- **资产之间的关系**：角色与道具的尺寸关系、角色在场景中的位置、道具在场景中的固定位置必须写入连续性字段。

## 通用生图规则

- 先写可见主体，再写展示目的、环境、材质、灯光、色彩、构图和一致性约束。
- 尽量使用具体名词、尺寸关系和可见特征；不要用空泛的“高级、绝美、电影感”代替视觉信息。
- 正向提示词与负面提示词分开；负面提示词只写当前资产的真实风险。
- 需要资产表时优先生成中性背景、均匀照明、清晰轮廓和可辨识细节；需要气氛图时再增加叙事环境和戏剧灯光。
- 资产图解决一致性，关键帧/线稿故事板解决站位、走位、比例和特效位置；不要用一张气氛图代替这两类控制。
- 资产设定板与生成参考素材分开管理：需要时才制作三视图/多角度拼图用于审阅外观；H3 不要求角色三视图或默认身份参考图。确需身份参考时使用清晰的单主体、单视角图，避免多角度拼图被误解为多个人物。
- 资产描述要完整但不重复；每个资产只保留会影响生成和连续性的特征。

## Midjourney V8.2 规则

执行前读取 [midjourney-v8.2-guide.md](references/midjourney-v8.2-guide.md)。关键约束：

- 当前默认版本是 V8.2；需要锁定版本时在末尾使用 `--v 8.2`。
- 提示词保持简洁且具体，按“主体、媒介/展示方式、环境、光线、颜色、情绪、构图”组织。
- 所有参数放在提示词最后，参数之间使用空格，不在参数后继续写正文。
- V8.x 资产一致性优先使用 Edit Model；不要默认使用 V7 的 `--oref`。
- 需要排除内容时优先使用末尾的 `--no`，并避免写成容易被逐词误读的否定短语。
- 多提示词权重和旧版本参数只有在用户明确需要兼容旧版本时才使用。

## 输出文件结构

两份 Markdown 都使用相同的资产顺序：项目说明、资产索引、角色、道具、场景、跨资产连续性、待确认问题。每个资产都必须有稳定 ID，例如 `CHAR_001`、`PROP_001`、`ENV_001`。

文件模板：

- [generic-image-prompts.md](templates/generic-image-prompts.md)
- [midjourney-prompts.md](templates/midjourney-prompts.md)

## 修改规则

- 用户只要求修改发型、颜色、材质或灯光时，只改该维度，并同步两份 Markdown。
- 用户修改资产 ID 或名称时，检查所有关联角色、道具和场景。
- 用户指定 Midjourney 版本时，以用户版本优先，并在文件头标注版本；未指定时按 V8.2。
- 不把剧本中没有的关键外观当作事实；新增推断必须标记为“推断设定”。
- 资产提示词的修订、补充或重跑都创建新的运行目录，并在 manifest 中记录基于的旧运行。
