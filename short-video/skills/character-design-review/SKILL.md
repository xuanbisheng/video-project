# Character Design Review

在影视剧本被解析后，先把角色设计作为一个可审核的中间交付物。该 Skill 是流程闸门，不负责直接生成最终资产库或视频提示词。

## 触发时机

- 已完成 `script-breakdown`，至少识别出人物、人物关系、剧情目标和关键动作。
- 已完成故事节拍或可拍性摘要，能够判断角色在故事中的功能和变化。
- 在 `asset-prompt-pack`、传统分镜设计和视频提示词生成之前执行。

## 工作流

1. 只从剧本事实和已确认设定中提取角色信息；推断内容单独标记为“推断设定”。
2. 为每个需要保持连续性的角色建立稳定 Asset ID，例如 `CHAR_001`、`CHAR_002`。
3. 生成 `character-design-review.md`，包含角色功能、人物弧线、外观、服装、道具、色彩、动作/表演、声音和跨角色关系。
4. 明确“锁定项”“可变项”“待确认项”，不要把未经确认的推断写成硬事实。
5. 将运行状态设为 `待角色审核`，停止后续流程并请求用户审核。

## 审核门

- 只有用户明确表示“通过角色设计”“确认角色设定”“按此继续”或等价确认后，状态才可变为 `角色已确认`。
- 用户提出修改意见时，状态变为 `需修改`；根据意见重新生成审核稿，并保留上一版作为历史，不继续下游流程。
- 未收到明确确认时，不得生成或定稿 `generic-image-prompts.md`、`midjourney-prompts.md`、`ai-storyboard-script.md`、`generic-video-prompts.md` 或 `h3-video-prompts.md`。
- 角色确认后，将批准版 Asset ID 和锁定设定传给 `asset-prompt-pack`、分镜和视频提示词流程；下游不得擅自改变已确认的角色核心特征。

## 角色设计字段

每个角色至少包含：

- Asset ID、姓名/代号、叙事功能、人物目标、阻碍、关系和人物变化。
- 年龄段、身份、体型、脸部特征、发型、肤色、服装、鞋、配饰和可识别轮廓。
- 主色、材质、时代/地域线索、关键道具和与其他角色的尺度关系。
- 默认姿态、动作习惯、微表情、视线、声音/说话方式和可见表演证据。
- 跨镜头锁定项、可变项、推断设定、待确认问题和参考图职责。

## 边界

- 角色设计服务于剧本，不新增人物、剧情、关系或结局。
- 本 Skill 只产出审核稿和审核状态；通用生图与 Midjourney 正式提示词由审核通过后的 `asset-prompt-pack` 生成。
- 角色外观尚未确认时，可以提出选项，但不得替用户做不可逆的最终选择。
