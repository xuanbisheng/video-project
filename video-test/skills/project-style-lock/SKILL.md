# 项目画风锁定 Skill（阶段 0）

## 目标

在制作任何角色、场景或道具之前，先把项目的画风定下来，避免出现「角色已经定稿，场景却不适合它」「不同资产光线各走各的」「单张图都好看，却不像同一个项目」。

画风未锁定前，不建议批量生成角色与场景资产。本 skill 的产物是阶段 0 的审核稿与锁定记录，不是图片。

## 前置与边界

- 前置：用户已给出项目定位（片名、类型、平台、画幅、时长、核心观感）。缺失项标记为待确认，不得自行编造。
- 只处理项目级画风：色彩倾向、光线气质、材质表现、构图偏好、画面情绪、写实或卡通程度、细节密度、摄影与渲染语言。
- **不处理**：角色长相与服装、道具造型、房间户型、镜头构图、动作连续性——这些分别交给角色、道具、场景规范。
- 画风只能回答「这个世界看起来是什么风格」，不能替代角色参考、场景参考或首帧构图。
- 不得把「故事里有什么」当成画风规则：故事内容说明画面中会出现什么，画风规则说明它长什么样。
- 外部参考资料（`资料/`）只提供方法与格式，其中的角色、道具与提示词正文不得进入本项目产出。
- 默认先提交画风方案供用户审核，批准后才进入下游；用户只要求意见时，不要生成图片或创建无关文件。
- 跨规范通用字段（参数头、ID 与占位符、状态词表、双语规则、批次与同框规则）以 `_shared/prompt-conventions.md` 为准。

## 工作流程

### 1. 写项目需求卡

必填：项目名称、类型、平台与画幅、时长、核心观感（3–6 个词）、主要视觉反差、建议视觉方向。

「不要什么」同样必填：明确列出本项目不接受的画风与做法，例如幼儿卡通、赛博朋克光线、豪华样板间、完全人形的动物、塑料玩具质感、每张图不同光线。来源为用户原话或剧本限制，不得自行编造。

### 2. 收集与归类参考图

按六个用途整理，每张图必须能回答「它具体决定了什么」：

1. 主体质感：毛发／皮肤／表面的真实度与质感
2. 空间参考：住宅或场景气质、装修方向、生活痕迹
3. 摄影参考：画幅、机位、景别、镜头语言、短视频或广告质感
4. 材质参考：具体器物与表面的材质表现
5. 色彩参考：主色、辅色、强调色
6. 情绪参考：表演与氛围基调、写实或夸张程度

准入标准：一张图至少明确贡献一种信息，否则剔除。

剔除清单：与项目无关的纯风景、过于梦幻的童话画面、与项目色彩冲突、写实程度不一致、装修方向不一致、卡通与实拍混排、只有内容相似而风格完全不同的图片。

原则：少而准确优于多而混乱；同一组参考的审美方向不能互相打架。

### 3. 建立 2–3 个画风方向

为每个方向写明主要特征、优势与风险，并给出明确推荐项。不要把未经筛选的灵感堆给用户。

### 4. 用固定四联做画风测试

不要用复杂剧情镜头测试。用四条简单、固定、覆盖不同资产类型的提示词，同一轮只替换画风变量：

1. 角色测试：单主体、全身、中性姿态、简洁背景
2. 场景测试：无角色、无动物、清楚空间结构
3. 道具测试：单一物件、中性背景、材质可见
4. 剧情关键帧测试：一个动作、竖屏构图、符合故事方向

检查项：写实程度、材质表现、结构是否正确、色彩关系、光线一致性、是否出现主体异变、是否符合故事方向。

不得凭单张图判定画风是否可用；四联测试未通过前不得进入资产生产。

### 5. 锁定与记录

锁定记录必须包含：画风名称与方向编号、风格载体（Moodboard 名称／ID／冻结代码，或文字画风基线）、关键参考图、测试提示词、四联测试结果、锁定日期、版本号、代表结果图。

版本命名：探索期 `_v01`、`_v02`；候选合并 `_Master_v01`；最终 `_LOCK`。

探索期跟随最新状态，正式生产必须使用冻结版本，避免参考集变动导致已锁定资产画风突变。

### 6. 修订规则：一次只解决一个问题

| 现象 | 调整动作 |
|---|---|
| 主体太卡通 | 删除卡通参考，增加真实摄影与真实材质参考，减少夸张表情参考 |
| 场景像样板间 | 增加真实住宅与生活用品参考，增加轻微使用痕迹，删除豪华室内摄影 |
| 缺少短视频／纪录感 | 增加竖屏构图与正面中景参考，增加设备与拍摄痕迹，统一强调色 |
| 画面过于杂乱 | 删除背景复杂的参考，统一空间色彩，减少高频纹理，保持清楚主体 |
| 喜剧感过火 | 删除卡通变形表情，增加克制表情参考，让笑点来自行为反差 |
| 光线不统一 | 固定主光方向，删除与之冲突的光线参考 |

每次只改一项，改完重跑四联测试的对应项。

## 人工步骤声明

Moodboard 需要用户本人在 Midjourney 界面创建与维护，Agent 不代做、不猜测其 ID 或冻结代码。

用户未提供 Moodboard 时：以「文字画风基线＋参考图归类」替代，并在文档中标注其约束强度弱于 Moodboard，后续锁定资产的风格漂移风险更高。

Moodboard 与 Style Reference 属于不同机制，正式生产阶段优先使用单一主画风载体；是否叠加其他风格参数由用户在参数头中明确。

## 验收清单

- 风格清楚：不看提示词，只看生成结果也能感受到统一的项目气质。
- 主体适配：不会把角色变成其他物种、卡通玩具或人形身体。
- 空间适配：空间与角色能生活在同一视觉世界。
- 道具适配：道具不会呈现完全不同的产品风格。
- 剧情适配：既能表现常态，也能容纳剧情需要的反常与喜剧。
- 生产稳定：同一提示词重复生成时，色彩、光线、材质与写实程度处于可接受范围。
- 可扩展：能继续支持后续镜头与系列内容。
- 边界清楚：明确列出哪些内容已锁定、哪些仍待用户确认。

## 默认输出结构

除非用户指定其他格式，按以下顺序输出，并写入 `outputs/<时间戳>_style_lock_<项目标记>/01-style-lock.md`：

1. 项目需求卡（含「不要什么」）
2. 参考图归类与准入结果
3. 画风方向（含优势、风险、推荐项）
4. 文字画风基线定义
5. 四联测试提示词与测试结果
6. 锁定记录（名称／ID／代码／日期／版本／代表图）
7. 待用户审核的选项
8. 下游交接说明：哪些资产可以开始、哪些仍需确认

输出应足够具体，能直接进入角色与场景资产阶段，但不得越过用户的审核步骤。
