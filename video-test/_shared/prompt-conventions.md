# 项目提示词与资产约定（共享）

> 适用范围：`skills/` 下的五份规范共同引用。
> 本文件不是 skill，不单独触发；它只定义跨规范必须一致的名词、字段、参数、状态与产出目录规则。
> 方法来源：`资料/mj/`（Midjourney Moodboard 方法与资产库格式范例）。**外部参考只提供方法与格式，其中的角色、道具、场景、命名与提示词正文属于其他项目，不得进入本项目产出。**

## 一、规范执行顺序、产出目录与文件命名

执行顺序（不得跳级）：

1. 阶段 0：项目画风锁定 → `skills/project-style-lock`
2. 阶段 1：角色概念设计 → `skills/character-concept-design`
3. 阶段 2：资产台账（角色 / 道具 / 场景）→ `skills/character-asset-skill`、`skills/prop-asset-skill`、`skills/scene-asset-skill`
4. 阶段 3：双语提示词与生产批次 → 同上
5. 阶段 4：剧情关键帧 → 角色与场景规范共同派生
6. 阶段 5：分镜与视频资产（本目录不覆盖）

### 产出目录规则（强制）

- 一切产出只写入 `outputs/`。不得写在根目录、`剧本/`、`资料/`、`skills/` 或 `_shared/` 内。
- **每次产出新建一个文件夹**，不复用、不追加既有文件夹，也不在 `outputs/` 根下直放文件。
- 文件夹命名：`<时间戳>_<模块>_<项目标记>`
  - 时间戳：产出时刻，格式 `YYYYMMDDHHMMSS`，共 14 位，如 `20261006143052`；不使用分隔符，保证按名称排序即按时间排序
  - 模块：snake_case，取自下表
  - 项目标记：`cat`（《再来一次，我就洗澡》）、`dog`（《等一下，我先闻闻》）
  - 三段以下划线连接，不使用空格、中文或大写字母
  - 示例：`20261006143052_character_design_cat`、`20261006143052_asset_cat`
  - 同一模块同日多次产出时由时间戳天然区分，不追加 `-v2` 之类后缀

模块词表：

| 模块 | 用途 | 产出规范 |
|---|---|---|
| `style_lock` | 项目画风锁定 | project-style-lock |
| `character_design` | 角色设计审核稿 | character-concept-design |
| `asset` | 资产台账与双语提示词 | character / prop / scene asset |
| `keyframe` | 剧情关键帧 | 角色＋场景规范 |
| `storyboard` | 分镜（预留，尚未启用） | — |

新模块启用前须先登记到本表，避免同一用途出现多种拼写。

### 文件夹内文件命名

- 主交付物用 `序号-名称.md`，如 `01-asset-library.md`、`02-midjourney-prompts.md`。
- 中间稿、预览与测试记录放入该文件夹下的 `_internal/`，不作为交付物。
- 文件夹内文件名不再重复模块名与项目标记（已由文件夹承载）。

### 废弃约定

以下旧写法不得再使用：`outputs/<项目名>/run-<时间戳>/`、`outputs/asset/`、在 `outputs/` 根目录直放文件。既有产出已归档到 `outputs/_archive/`，只作历史参考，不作为当前依据。

## 二、项目参数头（Prompt Header）

每份提示词文档（`02-midjourney-prompts.md`）必须在开头声明一次，正文不再重复：

```
- 项目：[PROJECT_TITLE]
- 目标模型版本：[MJ_VERSION]          # 未确认时保留占位符，不得猜测或默认
- 画幅基线：竖屏 9:16；角色基准 2:3 或 3:2；道具 1:1；空间总览 16:9
- 风格基线：[STYLE_BASELINE]          # 画风锁定后的文字画风定义
- 风格载体：[MOODBOARD_CODE]          # 探索期用 ID，生产期用冻结代码；无 Moodboard 时填「文字画风基线」
- 参考图占位符：见第三节
- 负面约束基线：见第九节
- 锁定日期与版本：[LOCK_DATE] / [LOCK_VERSION]
```

规则：

- 版本专属参数（`--v`、`--oref`、`--ow`、`--raw`、`--c`、`--sref`、`--sw` 等）只在参数头声明一次，**不得硬编码进每条正文**，也不得写成普遍规则。
- **参考图机制随模型分支而定**，参数头必须写明本项目采用哪一种，全项目锁定一种、不中途更换：
  - MJ 主线（V7 及以后）：`--oref [URL]` ＋ `--ow`，承载身份与主体一致性。
  - Niji 分支（Niji 6 / Niji 7）：`--sref [URL]` ＋ `--sw`，承载风格与设计一致性。
  - 二者不可混用：`--oref` 会自动指向主线 V7 模型，与 Niji 分支不兼容。
  - 上述对应关系以官方说明为准；无法实测时必须标注「未验证」。
- 参数必须集中在提示词**末尾**，参数之后不接正文或标点。
- 参数书写顺序：正文 → `--ar` → `--raw` → `--s` → `--c` → `--p [MOODBOARD_CODE]` → `--no ...`。
- 风格强度：`--s` 取值范围 0–1000（默认 100）。身份与功能类资产先用低值（50–100）测试服从度，确认后再提高；不得一开始使用高值。
- 一次只改变一个变量（画风、参数或动作），否则无法判断变化来源。

## 三、资产 ID 与占位符

- ID 形态：`<类型前缀>_<语义名>`，必要时追加序号。前缀固定四种：`CHAR`（角色）、`ENV`（场景）、`PROP`（道具）、`KF`（关键帧）。
- ID 一经分配不得改名；同一物件不得在后续文件中出现别名。
- 占位符形态：`[<资产ID>_URL]`，例如 `[CHAR_TUANTUAN_URL]`。
- 全局占位符：`[PROJECT_TITLE]`、`[MJ_VERSION]`、`[STYLE_BASELINE]`、`[MOODBOARD_ID]`、`[MOODBOARD_CODE]`、`[LOCK_DATE]`、`[LOCK_VERSION]`。
- 每份资产台账必须包含总表：**ID ↔ 占位符 ↔ 状态 ↔ 锁定项 ↔ 可变项**。
- 新产出统一使用上述形态；归档文件中出现过的长占位符（如 `[CHARACTER_REFERENCE_IMAGE_URL]`、`[SCENE_REFERENCE_IMAGE_URL]`、`[PROP_REFERENCE_IMAGE_URL]`）不得再沿用。

## 四、审核状态词表

| 状态 | 含义 | 允许的操作 |
|---|---|---|
| 待审核 | 已形成方案，未获用户确认 | 不得生成图片；不得派生下游资产 |
| 已确认 | 用户确认方向 | 可生成测试稿；仍不得批量派生 |
| 已锁定 | 已选定代表图并登记 | 可批量派生；必须填写锁定日期、版本与代表图 |

- 与内容来源标注区分：`[剧本事实]`、`[推断设定]`、`[待确认]` 描述的是**信息来自哪里**，不等于资产状态，两者必须同时填写。
- 未锁定资产不得写入提示词文档的正式条目，只能放在待审核区。
- 状态降级（已锁定 → 待审核）必须写明原因，例如画风载体变更或参考图替换。

## 五、双语输出规则

- 每条提示词必须同时给出中文审核版与英文执行版，逐项对应，不得漏译身份锚点、状态、数量、负面约束与安全限制。
- 中文版用于审核含义与连续性；英文版用于执行；参数、占位符与变量名保持原样，不翻译参数标记。
- 例外：重复性模板（动作模板、状态模板）只写**增量变量**，不重复整段固定锚点；固定锚点必须在主参考条目中完整出现一次。
- 不得用空泛的「高级」「惊艳」「电影感」替代可执行的材质、轮廓、色彩、镜头描述。

## 六、批次与最小资产包

- **第一批：不使用任何参考图**，先建立每类资产的基准（角色主参考、空间母版、道具主参考）。
- 从每类基准中各选定一张代表图 → 填入占位符 → 状态改为「已锁定」。
- **第二批：使用 `[<ID>_URL]` 派生**角度、状态、表情、动作、同框与关键帧（参考机制按第二节参数头所选分支执行）。
- 最小资产包：先完成核心项（角色主参考、空间母版、核心道具、主要场景区域），通过筛选后再扩充；不得一次性跑完全部提示词。
- 剧情关键帧必须在角色、场景与核心道具全部锁定后生成。

## 七、同框与多主体规则

- 同框前必须先各自锁定；未锁定的角色或道具不得进入同框图。
- 一个画面出现两个以上主体时：优先锁定其中一名主体并在提示词中完整描述，其余主体作为场景内容描述；偏差明显时改用后期编辑或合成，不反复重跑。
- 同框图只增加姿态、位置与尺度变量，不得重新设计角色或改变道具外观。

## 八、文字与后期边界

- 字幕、倒计时、台词、屏幕界面、包装信息、设备显示文字、牌子文字全部后期添加。
- 不要求生成模型输出可读文字；提示词中明确要求空白或不可读。
- 不得用文字生成替代空间构图控制。

## 九、通用负面约束基线

每条提示词至少覆盖：
`identity drift`、`changed markings`、`changed clothing`、`extra limbs`、`missing hands/paws`、`text`、`logo`、`watermark`、`cropped head or feet`。

按资产类型追加：

| 资产类型 | 追加负面约束 |
|---|---|
| 角色 | 品种或物种漂移、毛色／花纹漂移、配饰变化、拟人化身体、攻击或恐惧表情 |
| 道具 | 额外数量、数量增减、外观／材质变化、重复设备 |
| 场景 | 家具重排、窗户方向变化、道具复制、可读屏幕文字 |
| 同框 | 主体比例失真、某个主体被重新设计 |

## 十、安全与外部参考边界

- 一切生成物必须服从项目剧本的安全边界：不生成危险、强迫、伤害、失控或剧本未指定的状态。
- `资料/` 为外部方法参考：只提取方法与格式，其中的角色、道具、场景、命名与提示词正文一律不得进入本项目产出。
- 不得声称已生成图片，除非确实完成生成并能提供结果。
