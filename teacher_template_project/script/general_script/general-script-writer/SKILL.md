# 通用线性剧本写作

## 适用范围

处理常见的线性叙事剧本：电影、电视剧、短剧/微短剧、舞台剧、广播剧/有声剧、剧情短片和广告或品牌剧情片。支持四种模式：

- **从零创作**：根据题材、人物、主题、冲突和篇幅创作。
- **从大纲改编**：把梗概、小说片段、分集大纲或场景蓝图转换为剧本，保留原作核心事实和人物逻辑。
- **续写**：从现有剧本的当前状态继续，保留已发生事件、人物信息和因果关系。
- **修改与润色**：按要求修改对白、节奏、动机、冲突、结构或场景；若用户只要求诊断/评价，只给问题与建议，不直接重写全文。

不擅自把故事改成另一种载体，也不扩展到分镜表、镜头设计、图像或视频生成提示词、拍摄计划、制片预算或复杂游戏分支。用户需要这些内容时，说明它们属于其他专门流程。

## 开始前的判断

先判断剧本载体、工作模式、题材/类型/主题/基调、受众和使用场景、篇幅（时长/集数/场数）、时代地点与世界规则、主要人物及关系、主角目标与失败代价、锁定事实、禁用内容，以及演员/场景/道具/预算/表演限制。

只询问会明显改变写作方向的关键缺口，最多三个问题。用户明确说“自由发挥”时，可以做合理假设，并在正文前用很短的段落列出假设。不要反复询问低影响信息。

如果输入事实互相冲突，暂停写作并指出：冲突的两项事实、冲突为何影响后续剧情、需要用户确认的选择。不得暗中改写已确认事实。

## 内部事实账本

动笔前维护内部事实账本（无需全部展示）：人物身份与关系、人物已知信息、时间线、地点与世界规则、已发生事件、当前状态、伏笔与回收、锁定事实、禁止事项。续写和修改时先以现有文本为准；用户本次明确要求优先于一般建议，但不能无提示地破坏锁定事实。

## 创作流程

1. **确定戏剧核心**：明确观众跟随谁、主角现在想要什么、为何必须现在行动、有效阻力、失败代价、艰难选择，以及结尾人物/关系如何变化。
2. **组织结构**：让结构服务于目标、冲突升级、因果、选择、情绪和主题。用户指定结构时优先遵循，不强行套用固定三幕式、固定反转次数或固定节拍。
3. **设计场景**：每场明确主要人物、当前目标、障碍、行动、关键转折、结束后的状态变化及前后因果。每场至少改变信息、权力、关系、情绪、资源、危险、位置、行动方向或道德代价中的一项；重复背景、解释已知信息或无目的闲聊应删除、合并或重写。
4. **撰写可表演文本**：优先写观众能看见、听见或由表演表达的内容。用动作、选择、反应、停顿和潜台词表现内心，避免小说式长篇心理描写和信息灌输。对白应符合人物身份、年龄、关系、经历与情绪，并保持角色说话方式有区分度。不要让人物说出彼此早已知道、只是为了向观众解释的信息。
5. **按载体排版**：确定载体后，按 [references/script-format-guide.md](references/script-format-guide.md) 只读取对应章节，使用该载体的格式，不主动添加用户未要求的详细镜头语言。
6. **交付前自检并修正**：完成质量门禁后直接修正发现的问题，再交付。

## 输出约定

创作或续写默认包含：剧本名称、类型和载体、必要的前提说明、正式剧本正文；必要时补充后续承接信息。用户说“只输出正文”时，只输出正文。

修改默认包含修改后的剧本和简短修改说明；只有用户要求保留原文对照时才提供差异。诊断默认包含最重要的问题、出现位置、对剧情的影响和可执行建议，未经要求不重写整部剧本。

## 质量门禁

交付前检查并在需要时修正：

- 主角有明确欲望并采取行动，冲突能真正阻止目标。
- 事件主要由人物选择推动，场景之间有因果和状态变化。
- 动机能解释行为，人物掌握的信息和时间线前后一致。
- 对白有角色区分度和潜台词，没有大段灌输。
- 转折有铺垫；没有无铺垫的巧合、外部救援、突然证据或对手无故自曝。
- 没有重复功能场景，伏笔在后续产生作用，重要结果有前因。
- 结局回应核心冲突和主题。
- 格式符合所选载体，并遵守用户给出的事实、篇幅和制作限制。

## 边界与调用

当用户提出线性叙事剧本的创作、改编、续写、修改或诊断请求时调用 `$general-script-writer`。跨平台使用时，将本目录作为一个 skill 包加载，并以 `SKILL.md` 作为入口；`agents/openai.yaml` 仅提供可选的界面显示和默认提示词。
