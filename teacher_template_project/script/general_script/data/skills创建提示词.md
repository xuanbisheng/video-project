请为我创建一个 Skill，名称为 general-script-writer。
Skill 定位
这个 Skill 用于创作、续写、改编、修改和润色常见的线性叙事剧本。
支持的主要形式：
电影剧本
电视剧或网络剧
短剧、微短剧
舞台剧
广播剧、有声剧
剧情短片
广告或品牌剧情片
暂不负责：
分镜表和镜头设计
绘画、图像或视频生成提示词
拍摄计划和制片预算
复杂的游戏分支系统
未经用户要求，将故事自动改成另一种载体
如果用户需要上述内容，应说明需要使用其他专门流程，不要擅自扩展任务。
核心能力
Skill 应支持以下四种工作模式：
从零创作
根据用户提供的题材、人物、主题、冲突和篇幅要求创作剧本。
从大纲改编
把故事梗概、小说片段、分集大纲或场景蓝图转换为剧本，同时保留原作核心事实和人物逻辑。
续写
根据现有剧本、人物状态和剧情进度继续写作，不得遗忘或修改已经发生的事件。
修改与润色
按照用户要求修改对白、节奏、人物动机、冲突、结构或场景。
如果用户只要求诊断或评价，只提供问题分析和修改建议，不要直接重写全文。
开始前需要识别的信息
开始创作前，尽量确定：
剧本载体：电影、电视剧、短剧、舞台剧、广播剧或其他。
工作模式：从零创作、改编、续写、修改或诊断。
题材、类型、主题和整体基调。
目标观众和使用场景。
预计篇幅、时长、集数或场次数量。
故事发生的时代、地点和世界规则。
主要人物的姓名、身份、欲望、弱点和关系。
主角目标、主要阻力和失败代价。
已经确定且不得修改的事实。
用户禁止出现的内容。
场景、演员、道具、预算或表演方面的限制。
如果缺少的信息会明显改变剧本方向，先提出不超过三个关键问题。
如果用户明确表示“自由发挥”，可以根据题材做出合理假设，但应在剧本前简短说明这些假设。
不要反复询问对当前任务影响很小的信息。
事实管理
开始写作前整理内部事实，包括：
人物身份与关系
人物已知信息
时间线
地点与世界规则
已发生事件
人物当前状态
已埋伏笔
已兑现伏笔
锁定事实
禁止事项
这些内容主要用于保持一致性，不必全部展示给用户。
用户确认的事实不得被暗中修改。发现输入互相冲突时，停止写作并说明：
哪些信息发生冲突
冲突为什么影响后续剧情
需要用户确认哪一项
创作流程
一、确定戏剧核心
明确：
观众主要跟随谁
主角想要什么
为什么现在必须行动
谁或什么能够真正阻止主角
失败会失去什么
主角需要做出什么艰难选择
故事结束时人物或关系发生什么变化
不要只靠巧合、突然出现的证据、外部救援或对手无故自曝解决核心冲突。
二、组织结构
根据用户指定的载体和篇幅选择合适结构。
不要默认所有故事必须使用固定三幕式、固定反转次数或固定节拍。
结构应服务于：
人物目标
冲突升级
因果关系
人物选择
情绪积累
主题表达
最终结果
用户指定结构时，优先遵循用户要求。
三、设计场景
每个场景应明确：
场景中的主要人物
人物当前目标
阻止目标实现的障碍
人物采取的行动
场景中的关键转折
场景结束后发生的状态变化
该场景与前后场景的因果关系
至少改变以下一项：
信息
权力
关系
情绪
资源
危险程度
人物位置
行动方向
道德代价
如果一个场景只是在重复背景、解释已知信息或进行无目的闲聊，应删除、合并或重写。
四、撰写剧本
剧本应以可以被表演、看见或听见的内容为主。
写作要求：
动作用具体、清楚、可表现的语言描述。
避免文学小说式的长篇心理描写。
优先通过动作、选择、反应、停顿和潜台词表现人物内心。
对白符合人物身份、年龄、关系、经历和当前情绪。
不让不同人物使用完全相同的说话方式。
避免人物为了向观众解释剧情而说出彼此早已知道的信息。
括号中的语气或动作提示只在确有必要时使用。
不使用“主角”“反派”“某人”等占位称呼代替已经确定的人名。
不为了制造反转而破坏人物智商、动机或既有事实。
伏笔应在后续产生作用，重要结果应有前因。
不同载体的格式
根据用户选择的载体使用对应格式，不要强行统一。
影视剧本
使用：
场次编号
内景或外景
地点
时间
出场人物
动作描述
人物名
对白
必要的表演提示
除非用户要求，不主动加入详细镜头语言。
电视剧或短剧
在影视剧本格式基础上，可以增加：
集数和标题
本集目标
本集结果
与上一集的承接
与下一集的衔接
只有用户明确选择短剧形式时，才根据具体平台、单集时长和节奏要求考虑开场钩子、局部爽点、集尾悬念或付费卡点。
不要把这些规则默认应用到所有剧本。
舞台剧
使用：
幕和场
舞台空间
出场及退场
舞台动作
灯光、音乐或音效提示
人物对白
舞台提示必须考虑现场表演和空间转换的可执行性。
广播剧或有声剧
使用：
场景说明
人物名
对白
旁白
音效提示
音乐提示
声音远近、方向或环境变化
不能依靠观众看见动作理解剧情，重要信息应通过声音、对白、反应或环境音自然传达。
将具体格式说明集中放入 references/script-format-guide.md。只有确定剧本载体后，才读取其中对应章节。
默认输出方式
根据任务类型调整输出。
创作或续写
默认输出：
剧本名称
类型和载体
必要的前提说明
正式剧本正文
必要时提供后续承接信息
如果用户要求“只输出正文”，不要输出分析、创作过程或自我评价。
修改
默认输出：
修改后的剧本
简短修改说明
如果用户要求保留原文对照，再提供修改前后的差异。
诊断
默认输出：
最重要的问题
问题出现的位置
对剧情造成的影响
可执行的修改建议
未经用户要求，不直接重写整部剧本。
质量检查
交付前检查：
主角是否具有明确欲望和行动。
冲突是否能够真正阻止主角。
事件是否主要由人物选择推动。
场景之间是否具有因果关系。
人物动机是否能够解释其行为。
对白是否具有角色区分度和潜台词。
是否存在大段信息灌输。
转折是否具有铺垫。
是否出现无铺垫的巧合、救援、证据或人物自曝。
是否存在重复功能的场景。
人物掌握的信息是否前后一致。
时间线、地点、道具和人物状态是否连续。
结局是否回应核心冲突和主题。
格式是否符合所选载体。
是否遵守用户给出的锁定事实、篇幅和制作限制。
发现问题时，在交付前直接修正。
修改原则
修改现有剧本时：
优先保留用户原有风格和表达意图。
不因为局部问题擅自重写整个故事。
不修改与用户要求无关的内容。
用户的本次修改要求高于一般写作建议。
如果修改要求会破坏已锁定事实，应先指出冲突。
如果存在多个合理方案，简要说明主要取舍，让用户选择。
Skill 文件要求
遵循 Codex Skill 标准创建，文件总数控制在三个以内：
SKILL.md
保存 Skill 定位、触发条件、职责边界、工作模式、核心流程和质量门禁。
agents/openai.yaml
设置清晰的显示名称、简短说明和默认调用提示词。
保持默认的自动发现能力。
references/script-format-guide.md
保存影视剧、电视剧、短剧、舞台剧和广播剧的具体格式差异与简短示例。
不重复 SKILL.md 中已有的通用规则。
不要创建 README、占位文件或没有实际用途的资源。
Skill 的描述必须明确说明：
什么时候应该调用。
支持哪些剧本任务。
不负责分镜和视频生成提示词。
只进行剧本诊断时不会自动重写。
创建完成后：
运行 Skill 校验工具。
修复所有格式、命名和占位内容问题。
使用一个影视剧本创作请求和一个舞台剧修改请求进行行为检查。
行为检查不要生成额外测试文件。
最后报告创建的文件、验证结果和调用方式。
