请为我创建一个 Codex Skill，名称为 script-to-storyboard。
Skill 定位
这个 Skill 用于把已经确认的影视剧本转换为清晰、连续、可执行的文本分镜脚本。
适用范围：
电影
电视剧
网络剧
竖屏短剧
剧情短片
广告剧情片
AI 漫剧和动画前期设计
核心产物是逐镜头的文本分镜表，包括镜头内容、景别、机位、运动、表演、声音、时长和连续性信息。
职责边界
这个 Skill 只负责：
解析剧本中的场景、动作、对白和情绪变化。
把剧本拆分为视觉节拍和具体镜头。
设计镜头景别、角度、构图、运动和剪辑关系。
安排人物走位、视线、动作衔接和信息揭示顺序。
估算镜头时长并检查总时长。
输出可供导演、摄影、剪辑、动画或AI视觉制作使用的文本分镜脚本。
这个 Skill 不负责：
擅自修改人物关系、剧情结果或关键对白。
为了增加画面感而添加新的关键情节。
生成分镜图片。
生成绘画、Midjourney或视频模型提示词。
直接调用图像或视频生成工具。
编写完整拍摄计划、通告单或预算表。
把分镜脚本误写成对剧本的内容评价。
如果用户需要分镜图、图像提示词或视频提示词，应在完成文本分镜后交给其他专门流程。
必要输入
开始工作前读取：
已确认的剧本正文。
项目类型：电影、电视剧、短剧、短片、广告或动画。
目标画幅：16:9、9:16、2.39:1、1:1或其他。
目标时长或单场时长。
视觉风格和节奏倾向。
场景、演员、设备、特效和预算限制。
用户希望的分镜详细程度。
必须保留的对白、动作和剧情事实。
禁止增加或修改的内容。
是否允许对原剧本提出必要的可视化调整建议。
如果剧本正文缺失，不得直接制作分镜。
如果画幅、时长或载体缺失，并且会明显影响镜头设计，应提出不超过三个关键问题。
如果用户明确允许自由决定，可以采用合理默认值，但必须在输出前简短说明假设。
三种输出精度
根据用户要求选择一种模式。
简洁模式
适合前期沟通，只输出：
镜头编号
画面内容
景别
镜头运动
对白或声音
预计时长
标准模式
适合导演、摄影和剪辑沟通，输出完整分镜表。
详细模式
在标准模式基础上增加：
镜头设计意图
人物调度
构图重点
焦点变化
光线提示
剪辑衔接
连续性要求
拍摄或制作难点
用户没有指定时，默认使用标准模式。
工作流程
第一步：解析剧本
按场景识别：
场次编号
内景或外景
地点
时间
出场人物
场景目标
核心冲突
动作节点
对白节点
信息揭示
情绪转折
场景结果
与下一场的衔接
不得遗漏决定剧情走向的重要动作、对白或反应。
第二步：建立剧本锚点
为剧本中的关键内容建立可追踪锚点，例如：
S01-B01：第一场第一个剧情节拍
S01-B02：第一场第二个剧情节拍
S02-B01：第二场第一个剧情节拍
每个镜头必须关联至少一个剧本锚点。
这样可以检查：
是否遗漏剧情信息。
是否重复表现同一内容。
是否改变事件顺序。
新增内容是否有剧本依据。
如果输入剧本已有场次或段落编号，应优先沿用。
第三步：划分视觉节拍
在以下情况考虑切换镜头：
观众关注对象改变。
新的重要信息出现。
人物目标或策略改变。
情绪发生明显转折。
人物进入新的空间位置。
动作进入新的阶段。
需要展示关键反应。
叙事视角发生改变。
剪辑节奏需要加快或放缓。
不要机械地“一句对白切一个镜头”。
每个镜头应有一个主要视觉任务，避免一个镜头同时承担过多互相冲突的信息。
第四步：设计镜头
为每个镜头确定：
镜头编号
对应剧本锚点
预计时长
景别
机位角度
构图主体
画面开始状态
主要动作
画面结束状态
人物走位和表演重点
镜头运动
对白、旁白、音乐和音效
与前后镜头的剪辑关系
连续性要求
镜头设计必须服务于以下至少一项：
建立空间
呈现动作
强调人物关系
揭示信息
表达情绪
制造悬念
控制节奏
完成转场
不要为了显得专业而无目的地使用航拍、环绕、推拉摇移、倾斜构图或复杂长镜头。
第五步：处理对白场景
对白场景应先建立：
人物空间位置
视线方向
轴线
主导关系
情绪变化
信息揭示顺序
再根据内容选择：
双人镜头
正反打
过肩镜头
单人近景
反应镜头
插入镜头
必要的环境或空间镜头
不要给每句对白安排完全相同的正反打。
重要情绪可以通过停顿、反应或动作表现，不要只依靠台词。
未经用户允许，不得删改或重新分配关键对白。
第六步：处理动作场景
动作场景应保证观众能够理解：
人物在哪里。
人物想做什么。
危险来自哪里。
动作如何发生。
动作产生了什么结果。
人物和关键物品的空间关系如何变化。
先建立空间，再展示动作过程和结果。
保持动作方向、人物位置、道具状态和受伤状态连续。
不要只写“快速切换”“激烈打斗”等无法执行的模糊描述。
第七步：检查画幅适配
根据用户指定画幅调整构图。
对于9:16竖屏：
优先确保人物面部、手部和关键道具清晰。
重要动作尽量处于竖屏有效区域。
谨慎使用同时包含大量横向信息的大远景。
多人场景要明确视觉中心。
不得因此把所有镜头都改成近景。
对于宽银幕：
可以利用横向空间表现人物距离、环境和关系。
不要让重要人物或动作无目的地分散在画面边缘。
只有用户指定画幅后，才启用对应规则。
第八步：时长检查
为每个镜头估算时长，并计算：
每场预计时长
全片或全集预计时长
对白时长
动作时长
转场时长
估算时应考虑：
对白实际朗读时间
人物反应和停顿
动作完成时间
镜头运动时间
观众理解画面所需时间
如果总时长明显超出目标，不要直接删除剧情。
应指出超时位置，并优先建议：
合并功能重复的镜头
缩短无效停顿
减少重复反应
简化不影响剧情的调度
默认输出格式
项目信息
项目名称：
剧本范围：
载体：
画幅：
目标时长：
分镜模式：
视觉与节奏假设：
场景概览
场次地点与时间出场人物场景任务情绪变化预计时长
分镜脚本
镜号剧本锚点时长景别/角度画面与动作人物调度/表演镜头运动对白/声音剪辑/连续性
“画面与动作”必须写清：
镜头开始时看见什么。
镜头中发生什么动作。
镜头结束时画面停在哪里。
不要只写“拍摄人物对话”“展示现场”“主角很伤心”等模糊内容。
场景连续性
人物位置：
视线与轴线：
动作方向：
道具状态：
服装与妆容状态：
光线与时间：
上一场承接：
下一场衔接：
时长汇总
镜头数量：
场景预计时长：
总预计时长：
与目标时长的差异：
待确认事项
只列出确实需要用户决定、并且会影响执行的问题。
如果没有待确认事项，不输出这一部分。
如果用户要求“只输出分镜表”，则不要输出分析过程和额外解释。
连续性规则
必须检查：
人物进出画方向是否一致。
正反打是否遵守已建立的视线关系。
越轴是否有明确叙事目的或过渡镜头。
人物动作能否在相邻镜头间自然衔接。
道具由谁持有、放在哪里、何时发生变化。
人物坐立、伤势、衣着和情绪状态是否连续。
同一场景的时间和光线是否一致。
关键声音是否有来源或合理的画外空间。
镜头编号是否唯一并按顺序排列。
如果有意打破连续性规则，应说明它服务于什么表达目的。
剧情忠实规则
分镜可以重新组织视觉呈现方式，但不得擅自改变：
人物身份
人物关系
事件顺序
关键行为
关键对白含义
关键道具
冲突结果
人物掌握的信息
已锁定的世界规则
为了镜头衔接而增加的细小动作，不得改变剧情含义。
如果剧本内容无法直接视觉化，可以提供“可视化建议”，但必须与正式分镜区分，并等待用户确认后再采用。
质量门禁
交付前检查：
每个重要剧情节拍是否都有镜头承载。
每个镜头是否能追溯到剧本锚点。
是否存在遗漏、重复或顺序错误。
镜头是否具有明确视觉任务。
景别变化是否服务于信息和情绪。
是否滥用无意义的镜头运动。
人物空间关系是否清楚。
对白、动作和人物反应是否匹配。
轴线、视线、动作方向和道具状态是否连续。
镜头时长之和是否接近目标时长。
是否符合画幅和制作限制。
是否擅自添加、删减或修改剧情。
输出是否保持同一套术语和格式。
发现问题时应先修正，再交付最终分镜。
Skill 文件要求
遵循 Codex Skill 标准创建，文件总数控制在三个以内：
SKILL.md
保存职责边界、输入要求、转换流程、忠实规则和质量门禁。
agents/openai.yaml
设置显示名称、简短说明和默认调用提示词。
保持默认自动发现能力。
references/storyboard-format-guide.md
保存景别、角度、运镜、剪辑关系、连续性术语和不同画幅的格式说明。
包含一个简短的对白场景分镜示例和一个动作场景分镜示例。
不重复 SKILL.md 中的通用规则。
不要创建：
README
无用途的脚本
空白模板
分镜图片
图像或视频生成提示词文件
创建完成后：
运行 Skill 校验工具。
修复命名、YAML、引用路径和占位内容问题。
使用一个双人对白场景和一个简单动作场景进行行为检查。
检查剧情忠实度、镜头编号、时长计算和连续性。
行为检查不要生成额外测试文件。
最后报告创建文件、验证结果和调用方法。
