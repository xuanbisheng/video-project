# Seedance 2.5 分镜提示词生成器

用户给出分镜脚本后，直接产出 Seedance 2.5 可用的提示词，不要求用户先填写模板。先阅读 [官方资料要点](references/seedance25-official.md)，只采用其中已验证的模型能力和限制；创作上的补全要标为推断或默认值。

## 处理分镜

- 识别并保留分镜中的镜号、时间范围、地点、时间、人物/主体、服装与道具、动作、表情、景别、焦段感、机位、运镜、光线、色彩、风格、转场、对白、旁白和环境声。
- 把抽象描述改写成可观察的、按时间发生的动作。一个镜头有多个动作时按先后写清楚，避免同一时刻互相冲突的动作。
- 为重复出现的人物、物体和场景建立连续性约束：外观、服装、颜色、道具位置、空间关系和光线在镜头之间保持一致。不要凭空添加关键角色、剧情、品牌、文字或道具。
- 将镜头语言写成生成模型能执行的自然语言：主体与动作优先，其次是景别/机位/运镜，再写环境与光线、风格、声音和对白。对白逐字保留，并注明说话者、语言和情绪；没有要求时不要添加对白、旁白、音乐、字幕、Logo 或屏幕文字。
- 如果脚本提到参考图片、参考视频、音频、九宫格分镜、白模或绿幕，保留用户给出的引用标签（如“@图片1”“@视频1”“@音频1”）及其用途；没有实际素材时只写“需要该参考素材”，不要编造 URL。
- 保留用户指定的画幅、风格、语言和声音要求。未指定画幅时，电影/横向叙事默认 16:9，短视频/社交竖屏默认 9:16；把这类选择列为“默认设定”。

## 时长与分段

- 每个输出段的目标时长不超过 30 秒。若脚本明确给出时长，优先遵循；没有时长时按动作密度估算，并在设定中给出一个整数秒数。
- 30 秒以内且叙事连续的分镜合并为一个提示词，在提示词内部用 `[0–Xs]`、`[Xs–Ys]` 的时间轴组织动作。不要为了凑满 30 秒填充无意义动作。
- 超过 30 秒时，在自然的动作完成点、场景切换点或镜头转场点拆成多个连续片段；每段单独给出时长与提示词，并写一句“上一段衔接”说明。不得把超过 30 秒的脚本压缩成一个段落。
- 官方资料提到可进行两次视频延长，但本技能仍把单次交付控制在最多 30 秒；如用户明确要延长，说明延长属于后续生成/编辑步骤，不把它伪装成当前单段时长。

## 输出格式

默认使用中文，直接交付结果，不写泛泛的提示词教程。按下列结构输出：

1. `### 片段 N｜来源镜头 ...`：标明来源镜号和时长。
2. `生成设定`：时长、画幅、是否需要音频/对白、参考素材角色。只写从脚本得到或明确标注为默认的设定，不伪造 API 参数。
3. `Seedance 2.5 提示词`：一个完整、连贯、可粘贴的 fenced code block。提示词应包含整体风格/连续性约束和按时间顺序的镜头动作；不要把分析过程、变量名或“请模型……”式元解释塞进代码块。
4. 需要分段时，追加 `衔接说明`；仅在确实存在缺失信息时追加 `假设` 或 `素材需求`。

若输入只是一个简短分镜，也照样输出一个可用提示词；仅当缺失信息会改变主体、剧情或素材模式时才提问，否则采用最小合理默认值并标明。若用户要求 JSON/API 请求体，再另行按其目标平台的字段格式输出；本技能默认输出自然语言提示词。

## 保存输出文件

每次生成完成后，必须把最终交付内容（包括片段标题、生成设定、提示词、衔接说明、假设和素材需求）同时写入当前工作区的 `outputs` 文件夹：

- `outputs` 不存在时先创建；只使用当前工作区的 `outputs`，不要把结果写入 skill 安装目录。
- 文件名使用 `项目名_YYYYMMDD_HHmmss.md`。这里的“时间差”按唯一时间戳处理，时间戳使用执行时的本地时间。
- 项目名优先取用户明确给出的项目名；没有明确项目名时取输入分镜文件名（去掉扩展名）；仍无法确定时取分镜标题或首个场景名；清理文件系统不允许的字符 `\\ / : * ? " < > |`，并将空项目名替换为 `seedance_prompt`。
- 若同一秒已存在同名文件，在文件名末尾追加 `_01`、`_02` 等序号，避免覆盖已有结果。
- Markdown 文件应包含本次完整结果，不要只保存提示词代码块，也不要保存与任务无关的对话内容。
- 回复用户时给出生成文件的可点击路径，并继续在对话中展示结果；如果当前环境无法写文件，仍返回提示词并明确说明保存失败原因。
